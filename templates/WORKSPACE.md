# WORKSPACE.md - 目录管理规则

根目录不能乱扔文件！智能体每次启动时，请先阅读本文件。

> **本文件的归属与边界**：这是**用户维护**的工作区约定，智能体只能提议修改、不能擅自改写。
> 它只决定**本工作区产出的文件放在哪里**，不是对其他技能的指令覆盖 —— 技能自身的安全规则、许可条款与既定流程一律优先；解决不了的冲突停下来问用户。

## 目录结构

| 目录 | 用途 | 生命周期 |
|------|------|---------|
| `projects/` | 长期开发项目（有版本迭代） | 长期保留 |
| `tasks/` | 一次性任务（PPT、调研、临时站点） | 完成后原地保留，日志记录 |
| `outputs/` | 生成物（图片、文档等） | 按日期/主题分，定期清理 |
| `knowledge/` | 知识库 | 永久 |
| `scripts/` | 工具/一次性脚本 | 用完即删 |
| `memory/` | 日常日志 | 永久 |
| `tmp/` | 临时缓存 | 手动清理 |
| `.openclaw/`, `agent/`, `sessions/`, `.clawhub/` | 系统目录，不要手动修改或删除 | 永久 |

## 命名规范

| 场景 | 规则 | 例子 |
|------|------|------|
| 文件夹名 | kebab-case（小写+连字符） | `resume-site`, `ppt-anime-2026` |
| Python 脚本 | snake_case | `create_ppt.py`, `parse_data.py` |
| JS/TS 文件 | camelCase | `generateImage.js`, `fetchData.ts` |
| Markdown 文件 | kebab-case | `WORKSPACE.md`, `project-overview.md` |

## 行为规则

1. **反馈至上** → 无论任务成功还是失败，必须向用户报告结果。成功告知产出，失败告知原因和错误信息，由用户做下一步决策。智能体不得擅自决定下一步行动。
2. **新任务** → 先在 `tasks/` 或 `projects/` 建文件夹再干活
3. **生成的图片** → 放到 `outputs/images/`，按日期分子目录
4. **一次性脚本** → 放到对应 `tasks/xxx/` 目录下，不扔根目录
5. **下载的文件** → 先到 `tmp/`，再移到对应目录
6. **根目录** → 只放系统配置文件（*.md），不放任何项目文件
7. **任务完结** → 用户确认后，在 `memory/` 日志记录一笔，文件夹原地保留
8. **tmp 清理** → 只在用户要求时手动清理
9. **系统目录** → `.openclaw/`、`agent/`、`sessions/`、`.clawhub/` 不要手动修改或删除
10. **文件放置约定** → 其他技能约定的**输出路径**与本文件冲突时，把产出位置映射到工作区并**注明差异**（技能原约定 X → 存到 Y）；
    但技能的安全规则、许可条款、既定流程**优先于本文件**，不得以本文件为由要求技能绕过；技能必须在工作区外写入时以技能为准；无法靠换位置解决的冲突 → 问用户，不单方面决定
